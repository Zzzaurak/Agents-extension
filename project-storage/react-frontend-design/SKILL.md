# React 前端规范

沿用项目已有的路由、状态、请求和样式工具。根据页面复杂度选择拆分方式，保留可追踪的业务结构。

## 页面与状态

- 页面入口保留主要业务区域和它们之间的数据流。页面专用组件、hook、状态和计算放在页面或功能目录附近。通用 UI 基元才放共享 UI 目录，跨页面业务复用按功能归属。
- 用户操作更新核心数据，纯函数根据显式输入算出展示数据，组件负责渲染。可直接推导的数据随渲染计算，复杂计算可抽取命名函数。外部同步和请求放在已有的数据层或明确的交互边界。
- 局部 UI 状态留在页面或组件，适合分享或回放的导航状态放 URL。确需跨页面共享时使用项目已有状态方案。采用 Zustand 时可保持 store 私有，按需暴露订阅 hook、更新操作和供事件处理读取的快照。随状态变化的渲染使用订阅。
- 复杂页面按实际行为建模加载、失败、空结果和可展示结果。互斥状态可用判别联合。简单表单只需要足以表达实际行为的状态。
- 沿用项目声明的样式体系。采用 Tailwind 时优先复用已有的 token 和工具类，专用 CSS 放在归属明确的位置。清理无引用的脚手架前先检查用途。

## API 与交付

- 公共传输与业务调用分开。新建时可用 `src/api/` 管公共传输，用 `src/apis/<domain>/` 按后端业务域组织调用器。请求类适合希望明确一一对应的接口，简单项目也可用类型明确的函数。
- 端点用稳定标识、HTTP 方法和路径对齐。项目提供 OpenAPI 时，可使用它生成或检查传输类型。UI、表单和展示类型按页面需求建模。
- 规划复杂页面时，先列路由、业务区域、状态来源和依赖端点。涉及多页面或全栈边界时，在项目 README 记录实际的页面、调用器和端点对应关系。局部修改同步受影响的部分。
- 上手重构复杂页面、处理状态或接入后端时读 [页面、状态与 API 模式](references/patterns.md)。评审或交付时用 [审查清单](references/review-checklist.md) 检查受影响的行为和契约。
